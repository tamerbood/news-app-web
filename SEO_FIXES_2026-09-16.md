# SEO fixes – 2026-09-16

This release is based on `news-app-web-seo-fixed.zip` and contains the requested phase-1 SEO fixes.

## Changes

1. **Public `/sources` page**
   - Replaced the accidental admin/source-management UI at `/sources` with a public, indexable source directory.
   - Source management remains under `/admin/sources`.

2. **Homepage pagination**
   - Removed the artificial `1000` page clamp.
   - `/?page=N` now represents the requested page instead of silently loading page 1000.
   - Pagination metadata/canonical is page-specific; `/?page=1` canonicalizes to `/`.

3. **Main sitemap**
   - Replaced the old single sitemap capped at 100 API pages.
   - `/sitemap.xml` is now a sitemap index.
   - Child sitemaps are served from `/sitemaps/N.xml`, with 20 API pages (2,000 article URLs) per child.
   - Static public pages are included in the first child sitemap.
   - Article `<lastmod>` uses `updatedAt` when available, otherwise `publishedAt`.

4. **News sitemap / article dates**
   - News sitemap uses `publishedAt` only for `news:publication_date`; it no longer falls back to database `createdAt`.
   - `NewsArticle.dateModified` and Open Graph `modifiedTime` now use `updatedAt` when available, otherwise `publishedAt`.
   - `/news-sitemap` redirects permanently to `/news-sitemap.xml` to avoid maintaining duplicate endpoints.

5. **Category SEO**
   - `/categories` is now server-rendered instead of waiting for client-side `useEffect` data loading.
   - Category URLs such as `/categories?category=Sports` have real HTML content, category-specific title/description, and a self-referencing canonical.
   - Category links use crawlable `<a>`/Next `<Link>` navigation to the same URLs.

## Intentionally unchanged

- `robots.ts`
- News sitemap URL used in robots/Search Console
- Article URL structure
- Existing visual design outside the affected source/category pages
- Admin source-management functionality
